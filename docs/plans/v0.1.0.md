# Glow & Go — AI Voice Agent Salon Site (v0.1.0)

## Context

James Raven Tabag needs a portfolio piece that demonstrates an **ElevenLabs voice agent booking real appointments through n8n into Google Sheets**. The website is the stage; the voice agent is the act. A recruiter should land on the page, click one button, talk to an AI, and watch a booking happen.

Greenfield: the directory holds only four brand PNGs and `.claude/`. Not a git repo yet.

**The central constraint:** no ElevenLabs, n8n, or Google Cloud accounts exist yet, and James will supply keys *after* the build. So v0.1.0 ships **complete, correct, deployable code that runs in a clearly-labeled simulated mode**, and goes live by filling in env vars. Nothing is faked without saying so.

## Locked decisions

| Area | Decision |
|---|---|
| Call mechanism | Browser mic / WebRTC only. No phone number. |
| No-key behavior | Scripted simulated conversation behind a visible "Simulated preview — no live agent connected" badge. |
| Salon | Fictional US chain, **4 branches in one metro (LA)**, invented addresses. Single timezone (`America/Los_Angeles`). |
| Booking | **Per-stylist availability + real service durations.** 3 stylists/branch, 12 total, phonetically distinct names. "Any stylist / first available" is the default path. |
| Auth | Booking reference code (e.g. `GG-4821`), read back on booking, required to cancel/reschedule. |
| Sheet | Public link, **synthetic seed data only**; booking UI warns against real details. |
| Modal | Hologram in **brand copper/gold on near-black**, not cyan. |
| Content | Fully invented; one typed source of truth feeds both site and agent knowledgebase. |
| Tests | Playwright asserts UI + tool contracts against a mocked SDK. No real voice. |
| Workflow | Codex builds 2–3 design mockups for review *before* implementation. |

## Architecture (two findings that shape it)

**1. Webhook tools are server-side.** ElevenLabs hosts the agent and calls n8n directly:

```
Browser ──WebRTC──> ElevenLabs Agent ──webhook──> n8n ──> Google Sheets
   │                                                          │
   └── @elevenlabs/react renders orb/waveform/transcript      └── public read-only sheet
```

The browser is **not** in the booking path. Next.js therefore needs **no booking backend in live mode** — no API routes for bookings, no secrets in the app. This is a major simplification.

**2. ElevenLabs UI is shadcn-native.** Install via `npx shadcn@latest add https://ui.elevenlabs.io/r/orb.json` (also `live-waveform`, `transcript-viewer`). `Orb` takes `agentState` (`thinking|listening|talking`) and `getInputVolume`/`getOutputVolume`. Do **not** hand-roll a canvas visualizer — restyle these to copper instead.

**Mock layer.** Local route handlers under `app/api/mock/*` stand in for n8n in simulated mode, and double as the **executable contract spec** that the n8n workflow must satisfy. Env flag `NEXT_PUBLIC_AGENT_MODE=simulated|live` selects.

**SDK API note:** `@elevenlabs/react` exposes both `useConversation({ agentId })` and a newer `ConversationProvider` + `useConversationControls`/`useConversationStatus`. Codex must confirm the version's surface before wiring, not assume.

## Design direction

Derived from the supplied assets, not invented: near-black (`#0B0A09`), copper (`#B0703C`), gold-gradient wordmark, warm cream text. Editorial and warm — hard warm light, brass, backlit ovals. The hologram borrows sci-fi *form* (scanlines, volumetric glow, floating projection) in *brand color*.

**Assets:** move to `public/`, convert to WebP, serve via `next/image`. `Hero.png` and `Location.png` are ~2MB each and must not ship as-is. **Crop `Location.png` tight to the facade** — its Japanese street cues (utility poles, road markings) clash with US addresses; the storefront alone reads as generic upscale.

**Section order:** Navbar → Hero (+ primary call CTA) → About → Services → Locations → FAQ → Contact → Footer (disclaimer). FAQ precedes Contact so objections are answered before the ask.

**Floating call button:** desktop bottom-right, labeled. Mobile bottom-right, icon-only ~56px, offset above `env(safe-area-inset-bottom)`; collapses to icon on scroll-down, re-expands with label on scroll-up. No full-width bottom bar — it fights browser chrome and reads as an ad.

## Verification

- **Per chunk:** lint, type-check, build, relevant unit tests (Codex); Claude reviews the diff and commits.
- **Unit:** availability engine is the core logic — a 180m balayage must block three consecutive slots on *one* stylist's calendar while leaving the other two free; reference codes validate and reject.
- **Playwright (release gate):** modal opens/closes; waveform, transcript, timer render and update; FAB placement at desktop + mobile widths; nav and all sections; keyboard + screen-reader a11y; the four tools emit correct payloads to correct endpoints against a mocked SDK.
- **Manual:** `pnpm dev`, click through the simulated call end-to-end, confirm the badge is visible and a booking payload lands in the mock.
- **Not tested (stated plainly):** real voice, real LLM behavior, live n8n, live Sheets. Impossible without keys, and non-deterministic with them.

## Risks

- **Stylists + durations is the largest scope discussed** — chosen deliberately over the simpler option. Chunk 10 is the one most likely to need a second pass.
- **Simulated mode must never be mistaken for live.** The badge is a correctness requirement, not decoration; Playwright asserts it.
- **Codex must verify the `@elevenlabs/react` API surface** against the installed version rather than trusting either documented shape.
